# План управления аккаунтами в SwiftBar и дашборде

Согласованный список задач хранится в `quota-analytics/progress.md` в Basic Memory. Порядок реализации — короткие логины, личные отметки, видимость в SwiftBar, удаление из списка подключённых аккаунтов.

Все четыре этапа реализованы локально. Пройдены девять автоматических тестов и сквозная проверка дашборда в Chrome на тестовых аккаунтах. Для повторного подключения в тесте использована имитация Google OAuth.

## 1. Короткие логины в SwiftBar

**Файл** `plugins/antigravity_bar.5m.py`, формирование заголовка внутри цикла аккаунтов в `main()`.

- При отображении в выпадающем меню обрезать только суффикс `@gmail.com`, без учёта регистра домена. Для других доменов показывать полный адрес.
- Использовать полный адрес при сопоставлении аккаунтов, поиске квот и выполнении действий. В дашборде показывать полный адрес рядом с отметкой.
- Сохранить бейджи «Активен» и «кэш», порядок аккаунтов и формат строк квот. Проверить отображение Gmail, другого домена и активного профиля.

## 2. Личные отметки

**Файлы** `check_quota.py` (`load_accounts`, `save_accounts`, `add_account_flow`, `DashboardHTTPHandler`, `renderAccounts`, `generate_static_dashboard`) и `plugins/antigravity_bar.5m.py`.

1. Добавить в существующую запись `accounts.json` необязательное поле `note`. Для старых записей значение по умолчанию — пустая строка. При повторной авторизации существующего аккаунта сохранить его пользовательские настройки.
2. Сделать общее чтение и изменение записей по полному email с нормализацией адреса для сравнения. Перед каждой записью перечитывать текущую конфигурацию под общей блокировкой, которую используют локальный сервер и CLI `--add`. Сохранять JSON через временный файл в том же каталоге с закрытыми правами и атомарной заменой. Это позволит двум вкладкам или авторизации и дашборду менять разные поля без потери данных. При ошибке чтения или записи вернуть понятную ошибку в интерфейс.
3. Сохранить существующий приоритет локального `accounts.json` и резервного `~/.antigravity_accounts.json`. Если рабочая конфигурация читается из резервного файла, первую правку сохранить как локальный список целиком. Пустой локальный список считать действующим, чтобы удаление последнего аккаунта не восстанавливало резервный список.
4. Добавить локальный JSON-метод для обновления настроек конкретного аккаунта. Обычный сценарий `--dashboard` уже открывает страницу с локального сервера. Изменяющие запросы принимать со страницы этого же сервера. При открытии статического `dashboard.html` по `file://` показать сохранённые значения и подсказку, как открыть редактируемую панель через SwiftBar.
5. Добавить рядом с именем кнопку редактирования, однострочное поле и действия «Сохранить» и «Отмена». Сохранение пустого значения очищает отметку. В дашборде обновлять карточку после ответа сервера. При ошибке сохранить введённый текст в открытом редакторе. Использовать текстовые свойства DOM для отметки. При встраивании данных в статический HTML экранировать границу блока скрипта, а в SwiftBar безопасно отображать переносы и разделитель `|` из пользовательского текста.
6. Передавать в API и статический HTML только поля, нужные для отображения, включая `note`. Подставлять отметку из текущей конфигурации при подготовке данных для дашборда и SwiftBar, даже если сами квоты берутся из кэша. В SwiftBar строка будет выглядеть как `user1 (подписка Jio до 31.05.2027)`. Сохранение отметки обходится без опроса Google API. SwiftBar подхватывает её при следующем обновлении. На macOS проверить возможность вызвать это обновление сразу существующей ссылкой `swiftbar://refreshPlugin`.

## 3. Видимость аккаунтов в SwiftBar

**Файлы** `check_quota.py` (`renderAccounts` и локальный метод обновления настроек) и `plugins/antigravity_bar.5m.py` (`main`).

- Добавить к записи необязательное поле `show_in_swiftbar` со значением `true` по умолчанию. Сохранять его тем же методом, что и отметку, отдельным изменением поля.
- Добавить на карточку кнопку-глаз с двумя состояниями и подписями «Скрыть в SwiftBar» и «Показать в SwiftBar». Скрытие влияет на выпадающий список. Карточка и квоты остаются в дашборде, и глаз доступен для обратного действия.
- Вычислять фактическую видимость по правилу `аккаунт активен в IDE или show_in_swiftbar`. Активный аккаунт остаётся первым в меню и источником сводки в верхней строке macOS. В дашборде глаз для него показывает принудительную видимость с подсказкой. Если прежде скрытый аккаунт стал активным, он временно виден. Когда активным станет другой аккаунт, сохранённая настройка снова применяется.
- Использовать фактический активный адрес IDE. Дашборд сейчас может помечать первый элемент как текущий, если активный аккаунт не найден. Для управления видимостью опираться на подтверждённый `is_active`. Если активного подключённого аккаунта нет, брать сводку с первого видимого. Если видимых аккаунтов нет, показать нейтральный заголовок SwiftBar и оставить действия меню доступными.

## 4. Удаление с подтверждением

**Файлы** `check_quota.py` (`DashboardHTTPHandler`, `renderAccounts`, `get_all_quotas_data`, `generate_static_dashboard` и запись `accounts.json`) и `plugins/antigravity_bar.5m.py` (обновление списка).

1. Добавить отдельную кнопку-корзину. В подтверждении показать полный email и дать два действия — «Отмена» и «Удалить». Убрать карточку только после успешного ответа сервера. Пока запрос выполняется, блокировать повторное подтверждение для этой карточки.
2. Реализовать локальный метод удаления по полному email. Удалять запись из списка подключённых профилей вместе с её отметкой и настройкой видимости. Если аккаунт сейчас открыт в IDE, в подтверждении указать, что удаление касается мониторинга QuotaAnalytics. Сессия IDE продолжает работать. Правило обязательной видимости распространяется на подключённый активный профиль и защищает его от скрытия глазом.
3. Убрать удалённый адрес из кэша. При чтении свежего кэша, сетевом сбое и подготовке статического HTML сверять записи с актуальным списком подключённых аккаунтов. Перед записью результата опроса проверять под блокировкой, что запись аккаунта относится к тому же подключению, с которым начался опрос. Проверить гонку, когда удалённый email успели подключить снова до завершения прежнего опроса. При обновлении дашборда брать актуальный список с локального сервера, когда он доступен, даже если страница уже показала встроенный снимок.
4. Обновить карточки сразу после удаления и пересобрать локальный снимок для следующего открытия дашборда. SwiftBar подхватит новый список при очередном обновлении. При удалении последнего аккаунта оба интерфейса должны показать пустой список с доступным действием добавления. При очередном запуске плагина обновлять снимок и для пустого списка, до раннего выхода из `main()`.
5. Подключить кнопку «Добавить аккаунт» в дашборде к существующему потоку `--add`, который открывает Google OAuth и принимает обратный вызов. После подключения аккаунт снова появляется в обоих интерфейсах с настройками по умолчанию. SwiftBar и CLI используют тот же поток.

## Проверка и приёмка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Существующий `accounts.json` со старой структурой | Все аккаунты доступны. Gmail сокращается только в меню. Профили на других доменах и квоты отображаются как прежде. |
| Сохранение, изменение и очистка отметки | Дашборд сразу показывает результат. SwiftBar видит его после обновления. Перезапуск сервера и SwiftBar сохраняет настройки. Кириллица, кавычки и разделители показываются как текст. |
| Скрытие, показ и смена активного профиля | Скрытый аккаунт остаётся в дашборде. Когда он становится активным, сразу при обновлении попадает наверх списка SwiftBar. После смены активного применяется сохранённая настройка. |
| Отмена или подтверждение удаления | Отмена сохраняет запись. Подтверждение убирает аккаунт из обоих представлений. Открытая сессия IDE продолжает работать. |
| Удаление последнего аккаунта, отключение сети, опрос параллельно удалению | Удалённый аккаунт отсутствует в кэше, при повторном открытии дашборда и после обновления SwiftBar. Пустая локальная конфигурация имеет приоритет над резервной. |
| Повторное подключение и параллельное изменение настроек | Аккаунт появляется с настройками по умолчанию. Сохранение отметки и переключение глаза для существующего аккаунта сохраняют оба изменения. |

- Автоматизировать проверки хранилища, API и правил меню на временных конфигурациях с подставными аккаунтами и ответами квот. Плановая команда из корня проекта — `python3 -m unittest discover -s antigravity-quota-bar/tests -v`.
- Проверить сценарии целиком в дашборде и SwiftBar на macOS с отдельным тестовым списком. Отдельно проверить обычное открытие через локальный сервер и открытие статического снимка. При проверке после обновления кода убедиться, что фоновой сервер запущен с новой версией обработчика. Текущий `--dashboard` повторно использует сервер, если порт уже занят.
- Рабочая копия `check_quota.py` уже содержит локальные изменения в обнаружении Language Server и обработке кэша. При реализации строить правки поверх этих изменений и проверить, что запасные квоты и пересчёт таймеров продолжают работать. В рабочей копии есть отдельный прототип переключения аккаунтов. Интеграцию с ним проверять по фактическим точкам входа на момент реализации.
