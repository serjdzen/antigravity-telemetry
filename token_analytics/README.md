# 📊 Анализ расхода токенов в Antigravity 2.0 (Token Analytics)

Инструмент глубокого математического аудита потребления токенов, контекста и стоимости по всем историческим сессиям в Google Antigravity 2.0.

---

## 📁 Модульная архитектура движка

* **`report.py`** — основной консольный CLI-комбайн аналитики. Поддерживает динамические периоды (`month`, `week`, `day`), лимиты строк, анализ аномалий и экспорт срезов в JSON.
* **`core/`** — изолированное ядро аналитики:
  * **`core/scanner.py`** — сканер директории `~/.gemini/antigravity/brain/` с высокоточной BPE-токенизацией (`Qwen/Qwen2.5-7B`). Оснащён **инкрементальным кэшем** (`data/sessions_cache.json`): проверяет `mtime` и размер каждого файла `transcript.jsonl`. Если сессия не изменялась, она подтягивается из кэша мгновенно, сокращая время сканирования сотен сессий с 1–2 минут до **0.2 секунды**.
  * **`core/aggregator.py`** — многоуровневая агрегация сырых метрик: группировка по календарным месяцам (`YYYY-MM`), неделям ISO (`YYYY-Www`), суткам (`YYYY-MM-DD`), расчёт активных дней и выделение топа тяжелейших сессий.
  * **`core/comparator.py`** — модуль сравнительного анализа: вычисляет долю периода от всей истории (`% of Total`), процент роста к прошлому периоду (`MoM` / `WoW`), среднесуточные объёмы токенов и вызовов API, а также выполняет статистическую проверку гипотезы исчерпания квот Google.
* **`antigravity_token_analysis.json`** — структурированный JSON-срез со сводкой, помесячной динамикой и топ-сессиями.
* **`analyze_antigravity_tokens.py`** — исходный монолитный скрипт (сохранён для совместимости).
* **`README.md`** — полная спецификация, формулы, результаты аудита и инженерные выводы.

## 🔍 Как хранятся чаты в Antigravity и удаляются ли они?

### Куда пишутся логи:
Все диалоги и сессии агента сохраняются на локальном диске пользователя:
* **Каталог сессий:** `~/.gemini/antigravity/brain/<conversation-id>/`
* **Полный лог шагов:** `.system_generated/logs/transcript_full.jsonl`
* **Компактный лог:** `.system_generated/logs/transcript.jsonl`
* **База метаданных UI:** `~/.gemini/antigravity/conversation_summaries.db` (SQLite)

### Что происходит при удалении чата в интерфейсе Antigravity 2.0:
> [!IMPORTANT]
> **Удаление чата в UI — это Soft Delete (мягкое удаление).**  
> При нажатии «Удалить» в боковой панели Antigravity 2.0 запись о диалоге удаляется только из базы интерфейса `conversation_summaries.db`.  
> **Сама папка диалога с транскриптом на диске в `~/.gemini/antigravity/brain/` НЕ УДАЛЯЕТСЯ.**

При нашем аудите было обнаружено:
* В базе UI: **442 активных чата**;
* На диске в папке `brain/`: **495 папок**;
* **53 ранее удаленных вами чата** по-прежнему присутствуют на диске и **были полностью учтены скриптом в итоговой оценке**.

## 🧮 Методология подсчета: 2 уровня метрик

### 1. Сырые дельта-токены (Raw Unique Tokens)
Это физический объем новых символов, сгенерированных за сессию:
* **User Input** — ваши промпты и уточнения.
* **Model Output** — ответы агента и текст сообщений.
* **Thinking / Reasoning** — скрытые цепочки рассуждений CoT.
* **Tool Input / Output** — вызовы терминала, аргументы MCP и результаты выполнения команд.

*Итог по вашей истории: **~41.1 млн токенов** (стоимость при прямом вызове без контекста: **~$65**).*

---

### 2. Кумулятивный агентный контекст (Cumulative Agent Context)
Агент — это не разовый запрос в ChatGPT, а непрерывная цепочка (Chain-of-Thought / ReAct loop).
На каждом шаге $N$ модель отправляет в API:
$$\text{Контекст шага } N = \text{System Prompt} + \text{MCP Tools Schema} + \sum_{i=1}^{N-1} \text{Шаг}_i + \text{Текущий шаг}$$

* **System Prompt + MCP Overhead:** $\approx 3\,500$ токенов отправляется на каждом вызове модели.
* Если сессия состоит из 50 шагов, то первые шаги перечитываются моделью 50 раз.
* **Prompt Caching:** Google Cloud кэширует неизменяемый префикс диалога со скидкой до 75–90% по стоимости чтения.

### 📈 Точные результаты исторического аудита (на 30 сентября 2026 г.):
* **Обработано сессий:** 478 сессий (93 303 шагов диалога, 45 857 вызовов API)
* **Сырые уникальные токены (всего 68.96M):**
  * `User Input`: 1 200 447
  * `Model Output`: 16 254 376
  * `Thinking (Reasoning CoT)`: 2 347 934
  * `Tool Calls & Outputs`: 49 161 366
* **Кумулятивный контекст:** **20 210 229 185 токенов** (20.21 млрд)
* **Оценка стоимости по Google Cloud API (Gemini 2.5 / 3.x Flash):**
  * По сырым уникальным токенам: **~$85**
  * По реальной агентной модели с 90% Prompt Caching: **~$6 850**

4. **Сверхдлинные сессии:** появились диалоги на 2 000 – 4 470 шагов (топ-1 сессия сгенерировала 3.85 млн токенов и 4.43 млрд контекста). При таких сессиях на каждом шаге пересылаются сотни тысяч токенов, что моментально выбивает скользящие лимиты Google (TPM/RPD).
5. **Вывод:** Отлеты аккаунтов вызваны **беспрецедентным кратным ростом нагрузки со стороны пользователя (+316% по среднесуточным токенам и 1000 вызовов/день)**, а не снижением базовых лимитов Google.

### 💡 Главные инженерные выводы и правила гигиены токенов

1. **Длина диалога решает всё (квадратичный рост ReAct-контекста):**
   В отличие от разовых запросов, агент пересылает *весь* накопленный диалог, код и логи терминала на каждом последующем шаге ($\sim O(N^2)$). Сессия на 2 000 шагов расходует не в 40 раз больше контекста, чем сессия из 50 шагов, а в сотни раз больше.
   > **Правило №1:** завершать фазу задачи и открывать **новый чистый чат**, передавая состояние через файлы проекта или артефакты (`walkthrough.md`, `memory-bank`).
2. **Оверхед схем инструментов MCP:**
   На каждом вызове модели в системный промпт подмешиваются JSON-схемы всех активных MCP-инструментов.
   Например, сервер `telegram-mcp` по умолчанию выгружал 131 инструмент (~1 200 токенов на *каждый* шаг). За сессию в 1 000 шагов это создавало 1.2 млн токенов паразитного контекста только на схемы стикеров, опросов и гифок.
   > **Правило №2:** держать в MCP-серверах строго курируемый список нужных инструментов (сжатие `telegram-mcp` со 131 до 17 инструментов устранило утечку ~1 200 токенов на каждом шаге).

## 🚀 Инструкция: Запуск аналитики (CLI `report.py`)

Модульный инструмент `report.py` является единой точкой входа для построения отчетов, отслеживания динамики и экспорта данных.

### 1. Установка зависимостей
Скрипт использует быстрый HuggingFace BPE-токенизатор (`tokenizers`) и библиотеку форматирования таблиц (`tabulate`):
```bash
pip install tokenizers tabulate
```

### 2. Принцип работы инкрементального кэша
При первом запуске модуль `core/scanner.py` сканирует все папки в `~/.gemini/antigravity/brain/` и сохраняет метаданные сессий в `data/sessions_cache.json`.
При повторных вызовах сканер сверяет `mtime` и размер файлов транскрипта:
* Неизменённые сессии отдаются из кэша мгновенно;
* Сканируются только новые или активные в данный момент сессии.
* Время повторного запуска для 500+ сессий составляет **~0.2 секунды**.

### 3. Примеры консольных команд

```bash
# 1. Помесячный аудит по умолчанию (MoM динамика, доли, гипотеза лимитов + топ-10 сессий)
python3 report.py

# 2. Понедельный срез за всю историю (ISO-недели)
python3 report.py --period week

# 3. Посуточный срез за последние 14 дней
python3 report.py --period day --limit 14

# 4. Вывод топ-20 самых тяжелых сессий по объему контекста
python3 report.py --top 20

# 5. Принудительный полный пересчет в обход кэша
python3 report.py --refresh

# 6. Экспорт результатов в произвольный JSON-файл
python3 report.py --period month --json-out /tmp/monthly_audit.json
```

### 4. Описание колонок отчета

| Колонка | Что означает |
| :--- | :--- |
| **Период** | Календарный месяц (`YYYY-MM`), ISO-неделя (`YYYY-Www`) или день (`YYYY-MM-DD`). |
| **Сессий** | Количество уникальных диалогов в данный период. |
| **Дней** | Число активных дней с хотя бы одним сообщением. |
| **Уникальных** | Суммарные новые токены (промпты пользователя + ответы модели + вызовы инструментов). |
| **Доля %** | Процент токенов периода от общего объема за всю историю Antigravity. |
| **Прирост** | Процент роста или падения к предыдущему периоду (`MoM` / `WoW`). |
| **Токенов/день** | Среднесуточный расход уникальных токенов (нормализован на активные дни). |
| **Thinking %** | Доля рассуждений (CoT) в ответах модели (помогает выявлять усложнение задач). |
| **Контекст (Всего)** | Суммарный объем токенов, отправленный во все вызовы API с учетом истории ReAct-шагов. |
| **Вызовов/день** | Среднее количество обращений к API модели в сутки. |
